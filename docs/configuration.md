# 图像、纸张与协议配置

[返回指南](README.md) · 适用 SDK `0.2.0-preview.4`

## 几何参数

打印 API 使用打印点 dots，不使用屏幕像素或文件内嵌 DPI 自动推断纸张尺寸。
毫米转点可按 `dots = round(mm × dpi / 25.4)` 计算，再按设备的实际限制处理取整。
示例中的 203 DPI、576 / 864 dots 等是开发输入，不是扫描结果、型号能力或通用安全值。

`widthDots` 为配置的最大可打印宽度，需大于 0、不超过 7992 且为 8 的倍数；
最终还要服从实际打印头宽度。CPCL `maxLabelHeightDots` 为调用方配置的单页高度上限，
范围 1–65535，并不证明固件支持这个上限。DPI 必须为正；ESC/POS profile 的 DPI 范围为 1–255。
不要用 SDK 参数范围代替固件、纸张或切刀规格。

| 概念 | 用途 |
| --- | --- |
| 可打印宽度 | 打印头允许的最大横向范围 |
| 图像 / 画布宽度 | 本次内容宽度，须落在可打印范围内 |
| 单页高度预算 | CPCL 一张标签的图像高度、偏移和留白限制 |
| 整单长度预算 | ESC/POS 所有份数与结束留白的总长度，不是设备单页能力 |
| 图像条带高度 | 内部图像处理和编码单元 |
| 传输分块大小 | 蓝牙等传输的发送单元，与图像条带相互独立 |

## 标签与小票

CPCL 使用 `CpclProfile`，Android 调用 `submitLabelGray8`，Swift 调用 `submitGray8`。
图像、原点偏移及末尾留白必须落在配置的可打印范围和页高预算内。
FORM / `form` 控制本次标签结束策略，不是永久设备设置，也不能代替独立定位或纸张传感器校准。
`xOffsetDots` 只作为标签作业默认横向原点，不改写 Raw 命令。

ESC/POS 使用 Android `EscPosProfile` / Swift `ReceiptProfile`，再调用
`submitReceiptGray8`。调用方预先渲染整单图像；`maxTotalLength` / `maxTotalLengthDots`
须覆盖所有份数及每份/整单的结束留白。无切刀依据时使用 `CUT_NONE` / `.none`。
不受支持的结束策略会报错，SDK 不静默省略切刀要求。

介质跟踪（间隙、黑标、连续纸）、FORM 和定位属于不同操作。显式调用
`setMedia` / `setMediaMode` 或 `locateNextLabel` / `feedToNextLabel` 也会产生设备 IO；
先确认协议和固件依据。设置发送完成只表示 `DATA_SENT`，不证明设置已读回或生效。

## 图像与内存

移动端图像提交接收紧密排列、从上到下、从左到右的 GRAY8：每像素一字节，
载荷长度应为 `width × height`，不包含行尾 padding；0 为黑、255 为白。
JPEG/PNG、方向校正、透明背景合成及缩放由应用在提交前处理。SDK 图像方法不接收文件路径，
也不提供原生文本、二维码或条码排版 API；应用可先将这些内容渲染到图像中。

原生编码按条带流式进行，但应用仍持有解码图像、灰度数据和预览，提交还会生成不可变原生载荷。
这不是任意尺寸图像的恒定内存保证。限制源图像像素数、宽高比、缩放目标及同时排队数量，
并在目标手机测量 App 完整峰值；`1008` 表示资源门限等限制，不应靠连续重试规避。

Full Demo 的预览与发送使用同一灰度快照。更改纸张、DPI、画布或原点后应重新准备图像，
不要发送与当前参数不匹配的旧预览。圆角、标签边缘和可见安全区仍需实物确认。

## BLE 与 Raw

BLE 服务/写入特征 UUID、写入响应策略、最大载荷和可选 credit 流控必须匹配固件文档。
`M90Profile.bleOptions(...)` 是基于 M90 V1.2 文档的显式开发选项，不是自动探测。
不要仅因广播名称相同就把它用于另一型号，也不要用更大的分块值猜测提速。

Raw 必须是选定固件支持的完整命令流，它和图像作业共用设备队列。SDK 不校验 Raw 的业务语义，
不会补齐命令或推断纸张参数。不要用猜测的清缓存、复位或切刀指令处理失败。
Raw 不适用图像的 FORM / 原点选项，日志不应包含 Raw 载荷。
